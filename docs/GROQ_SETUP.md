# Groq 사진 인증 및 퀴즈

## 상태 (2026-10-17)

로컬 코드 구현과 프런트엔드 빌드 완료. 새 SQL migration 및 `greenstep-ai` 함수는 아직 원격에 배포하지 않았으며 Groq 키를 이용한 실호출·기기 카메라 동작은 검증하지 않았습니다. 기존 `greenstep-chat`의 Gemini 챗봇은 유지합니다.

## 키 입력 위치

Supabase 프로젝트 `dfgdtvgpnsyjhnsttibs` → Edge Functions → Secrets:

| Name | Value |
| --- | --- |
| `GROQ_API_KEY` | Groq Console에서 발급받은 키 |
| `GROQ_VISION_MODEL` | `qwen/qwen3.8-27b` |
| `GROQ_QUIZ_MODEL` | `qwen/qwen3.8-27b` |

모델 기본값은 위와 같습니다. 모델 사용 권한은 Groq 프로젝트에서 확인하세요. 키를 `.env.example`, `VITE_*` 또는 GitHub에 저장하지 않습니다. 비밀값을 넣는 로컬 소스 파일은 없습니다.

공식 문서: https://console.groq.com/docs/vision

## 배포 순서

1. 기존 회원 DB가 설치된 프로젝트의 SQL Editor에서 `supabase/migrations/202610170001_groq_verification.sql`을 한 번 실행합니다. 기존 참여·포인트는 보존합니다. 적용 직후부터 예전 사진 업로드 방식은 차단되므로 함수 및 프런트 배포를 같은 작업 시간에 진행하세요.
2. 위 Secrets를 등록합니다.
3. 로그인된 Supabase CLI에서 저장소 루트 기준으로 실행합니다:

```sh
npx supabase functions deploy greenstep-ai --project-ref dfgdtvgpnsyjhnsttibs
```

`supabase/config.toml`은 gateway JWT 검증 대신 함수 내부의 `auth.getUser()`로 모든 요청의 사용자를 검증하도록 설정되어 있습니다. 서버 서비스 키는 Supabase가 자동 제공합니다.

4. 프런트엔드 변경을 배포합니다. 퀴즈와 사진 인증이 새 `greenstep-ai`를 호출합니다.
5. 기기에서 카메라 권한을 허용합니다. 배포 주소는 HTTPS여야 합니다. 오늘 이미 생성된 퀴즈는 재사용하며, 새 문제부터 Groq를 사용합니다.

## 처리와 한계

- 카메라 스트림에서 JPEG를 캡처합니다. 갤러리/파일/샘플 선택은 없습니다. 닫기·화면 숨김·촬영 후 카메라를 종료합니다.
- 서버가 로그인한 사용자의 참여 기록에 연결한 5분 촬영 요청을 발급합니다. 사용자당 시간당 최대 20회입니다.
- 한 요청을 원자적으로 처리 중 상태로 전환합니다. 승인 사진의 SHA-256을 중복 검사하고 유일 인덱스로 동시 중복 승인도 막습니다.
- Groq에 사진과 서버의 챌린지 제목을 전달합니다. 승인 사진만 비공개 버킷에 저장합니다. 거절·API 장애·형식 오류 시 포인트를 지급하지 않습니다.
- `gs_complete`가 승인 기록의 사용자·참여 ID·사진 경로를 확인합니다. 클라이언트가 승인 여부나 보상 수치를 지정할 수 없습니다. 기존 참여 ID의 완료 재시도는 중복 적립하지 않습니다.
- 웹 카메라가 실제로 방금 촬영됐다는 하드웨어 증명은 아닙니다. 조작된 클라이언트, 가상 카메라, 예전 사진 재촬영, 재인코딩은 완전히 차단할 수 없습니다. 해시는 동일 파일만 감지하며 시각적 유사도/실재성 검증은 구현하지 않았습니다.
- AI 판정에는 오차가 있습니다. 거리·정확한 무게·결제·공식 매장 등 사진으로 필수 조건이 확인되지 않으면 승인하지 않도록 요청합니다. 이 경우 추가 증빙/수동 심사 기능이 필요하며 현재는 자동 지급하지 않습니다. 별도로 입력한 잔반 무게는 사용자 측정값입니다.
- 퀴즈는 DB의 최근 완료 활동·활성 챌린지·최근 문제를 참고해 생성합니다. 모델을 학습시키는 방식이 아닙니다. 정답은 서버 DB에만 저장하고 기존 채점·보상을 사용합니다.
- API 응답 지연 중 앱이 닫혀도 서버 처리는 계속될 수 있습니다. 사진 승인 후 네트워크 오류가 나면 같은 사진의 제출 버튼으로 재시도할 수 있습니다. 거절되거나 요청이 만료된 경우 다시 촬영하세요.
